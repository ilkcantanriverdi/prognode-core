# PROGNODE V0.7.2 RC6.4 — Trend Studio (feedback preview)

Base: complete RC6.3.1-HF2 Core. Existing numeric/digital alarm engine, FC01/02/03/04 Modbus, Batch/Lot, historian, local license and sign-in implementations are retained; this preview changes only Trend UI and adds one read-only data API.

## What is implemented

- New full-width Trend Studio layout with searchable signal explorer (renders at most 160 rows per search; select at most 8), saved views, live/history presets and custom date range.
- Independent left/right Y axes per signal (session state). Canvas chart includes smooth analog lines, digital step signals, quality interruptions (GOOD/BAD/STALE), crosshair with synchronized values and thresholds from actual alarm definitions.
- Drag to zoom, normal mouse-wheel page scrolling (no accidental chart zoom), double-click to reset, navigator miniature plot and time-range selection, and A/B cursors with elapsed time and per-tag Δvalue.
- Real alarm occurrences (up to the latest 500) and Batch/Lot spans (up to the latest 100) overlaid from normal Core API endpoints; recent event cards alongside the plot.
- Existing saved Trend CRUD and historian settings retained. “Save view” preselects current signal/colors in the existing editor, where access control still applies.
- Saved-view CSV uses the existing RAW historian CSV backend. Ad-hoc/unsaved CSV exports only plotted (possibly downsampled) points and labels them as such. PNG exports the chart canvas.
- New bounded read-only endpoint `GET /api/trend-studio/series?tagIds=GUID1,GUID2&from=ISO&to=ISO&maxPoints=1800`. Maximum 8 existing Tag IDs, 366-day span, max 5000 returned points *per series*; reuses existing historian query/decimation.
- Responsive mobile layout; no external chart library or CDN dependency. No simulated data inserted into production Core.

## Important preview limits

This is **a real source-code feedback preview, not a production-certified RC6.4 release**. .NET 10 SDK is unavailable in the generation environment, so the new C# endpoint requires a Windows compile. Integration with a live Windows Core and PLC simulator has not been run here. Live mode refreshes the local historian (at the existing sampling frequency); it does not invent faster samples or poll PLCs in the browser.

Alarm overlay comes from the 500 most recent occurrences, and Batch overlay from the 100 most recent BatchRun records; older events outside those limits are not guaranteed to appear in long historical windows. Session-only Y-axis assignment, no persistent per-signal axis preferences. PDF/Excel report generation, six-month high-volume benchmark and mobile remote delivery are **not** part of this preview. Full raw historian export of an unsaved ad-hoc view requires saving it first.

## Try it visually first

Open `TREND_STUDIO_RC6_4_2_OFFLINE_DEMO.html` in a desktop browser (the older `TREND_STUDIO_VISUAL_PREVIEW.html` is an RC6.4 design reference). The file is fully standalone and uses **clearly marked simulated visual example data** without contacting Core. The new demo runs this RC6.4.2 Trend Studio JavaScript with a mocked read-only API, including high/low alarm crossings and clickable flags.

## Try with real Core

1. Back up your live `prognode.db` and `current.pgnlicense`. Work with the existing RC6.3.1-HF2 data; don't delete or reset it.
2. Run `START_PROGNODE_RC6_4_PREVIEW.cmd` on the Windows development PC. It builds with the locally installed .NET SDK, stops the dev service/process occupying 5080 and checks `/api/health` version before opening the browser. Use this ONLY on the intended developer PC since the helper stops a process bound to 5080.
3. Confirm the sidebar shows `v0.7.2-rc6.4.2-trend-analysis` and navigate to Trends. If no saved views exist, use the signal explorer to create an unsaved analysis.
4. If history is empty, enable recording on the Historian page and let your PLC simulator run through real Modbus polling. Live Data should show the actual Core sampleCount; no fake data is generated by the application.
5. Run `./TEST_PROGNODE_RC6_4_TREND.ps1` to check the new endpoint and existing context API.
6. Try 2-4 signals with mismatched units, right-axis assignment, the updated A/B comparison panel, clickable flag details, alarm-aware scaling and threshold-colored segments, Batch overlay, CSV and PNG. Send your screenshots and any console/build errors back for the next iteration.

## Windows acceptance still outstanding

- `dotnet build PROGNODE.sln`: must report 0 errors; not executed in this Linux container because .NET is absent.
- End-to-end production-chain test through PLC Simulator -> Modbus -> Tag Polling -> Historian -> Trend Studio; not executed here.
- Long-range performance and RC6.3.1 license/revoke/login regression on the actual Windows installation.

No SQLite schema migration was added. This preview uses the existing persisted Trend definitions and existing schema v8, so rolling back to HF2 (after making a data backup) remains possible.
